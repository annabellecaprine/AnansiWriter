AnansiWriter: Post-Core Feature & Polish Brief
AnansiWriter has completed its major architectural refactors.
The current canonical hierarchy is:
Library
├── Series
│   └── Novel
│       └── Act? → Chapter → Scene
└── Standalone Novel
    └── Act? → Chapter → Scene

The primary Novel workspaces are:
Plan
Write
Codex
Assets
Prompts
Staging
Review

Plan and Write operate on the same underlying manuscript hierarchy.
Codex, Prompts, Assets, AI providers, Context Engine, and basic LLM testing already exist.
Important instruction
Do not perform another architectural rewrite.
Do not reintroduce:
- Project as an author-facing concept
- duplicate Planning/Writing Scene models
- hard-coded AI features when a saved Prompt can perform the operation
- separate asset storage systems
- parallel context systems
- browser-native dialogs
This pass is about turning the working application into a polished daily-use writing environment.

Acceptance Philosophy
For this stage, completion means:
An author can actually use the feature comfortably during real work.

Not merely:
- schema exists
- component renders
- button exists
- backend function exists
Each feature must be manually usable end-to-end.
Final Product Goal
The desired AnansiWriter workflow is:
Open Library
        ↓
Choose Series / Novel
        ↓
Plan story structure
        ↕
Write manuscript
        ↕
Inspect Codex / Research / Assets
        ↕
Invoke saved Prompts or Chat contextually
        ↕
Review objective story analytics
        ↓
Export manuscript

without requiring the author to mentally stitch together separate tools.
The application should feel like one novel with many useful lenses, not a collection of databases and AI utilities.
